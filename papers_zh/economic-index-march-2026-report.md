Anthropic 经济指数使用我们的隐私保护数据分析[系统](<https://www.anthropic.com/research/clio>)来跟踪 Claude 在整个经济中的使用情况。这是我们尽早了解 AI 经济影响所做努力的一部分，以便研究人员和政策制定者有充足的时间做准备。
这份最新报告研究了 2026 年 2 月 Claude 的使用情况，建立在[上一份报告](<https://www.anthropic.com/research/anthropic-economic-index-january-2026-report>)（使用 2025 年 11 月的数据）中引入的经济原语（economic primitives）框架之上。我们的样本覆盖 2 月 5 日至 2 月 12 日，即 Claude Opus 4.5 发布三个月后，与 Claude Opus 4.6 的发布同期。
我们首先记录了使用情况相对于此前报告的变化：增强（augmentation）——即 AI 补充用户能力的协作式交互——的比例在 Claude.ai 和 API 流量中均略有上升。在 Claude.ai 中，使用情况更加多样化，上个月前 10 大任务占使用量的份额低于 2025 年 11 月。由于这种多样化，Claude.ai 中平均对话的任务工资水平[略低于](<https://cdn.sanity.io/files/4zrzovbb/website/f065d6e6f92c65df8244042c83d48872ea308c3a.pdf>)此前报告。
然后我们聚焦于决定 Claude 对劳动力市场和更广泛经济影响的一个重要因素：Claude 采用中的学习曲线。我们提供的证据表明，使用年限长的用户已经形成了能够更好地发挥 Claude 能力的习惯和策略。事实上，我们记录到更有经验的用户不仅尝试更高价值的任务，而且在对话中更有可能获得成功的回应。
#### **自上次报告以来的变化**
在第一章中，我们重新审视了 2026 年 1 月发布的上一份[经济指数报告](<https://www-cdn.anthropic.com/096d94c1a91c6480806d8f24b2344c7e2a4bc666.pdf>)中的发现。我们发现：
  * **Claude.ai 上的用例更加多样化。**编码任务继续从 Claude.ai 的增强型使用迁移到我们第一方 API 流量中更自动化的工作流。1 在本报告中，Claude.ai 的使用更加分散：2 月份前 10 大任务占全部流量的 19%，低于 11 月的 24%。尽管如此，该样本中几乎所有任务都曾出现在我们之前的样本中。约 49% 的职业中，至少有四分之一的职业任务是通过 Claude 完成的。
  * **Claude 的采用扩展到更低工资的任务。**随着用例的多样化，在 Claude 上完成工作的平均经济价值——以相关职业中美国工人所得工资衡量——略有下降。从机制上看，这是因为围绕体育、产品比较和家庭维护的个人查询增多。这一模式与标准的"采用曲线"叙事一致：早期采用者偏爱编码等特定的高价值用途，而后期采用者承担范围更广的任务。
  * **全球使用的不平等持续存在。**使用仍然高度集中：前 20 个国家占所有人均使用量的 48%，高于此前的 45%，凸显了全球采用方面持续存在的差距。然而，美国国内的人均 Claude 使用量继续趋同：自上次报告以来，使用量最高的 10 个州所占份额从 40% 下降到 38%。

#### 学习曲线
经济指数的一个核心发现是，Claude 的早期采用非常不均衡：Claude 在高收入国家使用更密集，在美国的知识工作者聚集地使用更密集，并且集中于相对较小的专业任务和职业集合。
一个重要的问题是，采用的不平等可能如何决定 AI 收益流向何处、流向何人。例如，如果有效的 AI 使用需要互补技能和专业知识——我们在[上一份报告](<https://www-cdn.anthropic.com/096d94c1a91c6480806d8f24b2344c7e2a4bc666.pdf>)中论证过这一点——并且如果这些技能可以通过使用和试验获得，那么早期采用的好处可能是自我强化的。
在第二章中，我们研究用户如何塑造他们从 Claude 中获得的价值：他们如何将模型能力与手头任务匹配，以及使用模式和结果如何随平台上的经验而变化。
  * **模型选择与任务匹配。**我们表明，用户会选择我们最智能的模型类别 Opus 来处理在劳动力市场上通常获得更高工资的任务。例如，在付费的 Claude.ai 用户中，Opus 在编码任务中的使用率比平均值高 4 个百分点，在与辅导相关的任务中比平均值低 7 个百分点。对于 API 用户，这种模型切换的幅度大约是其两倍。
  * **使用年限越长，成功率越高。**总体而言，最有经验的 Claude 用户更多将其用于高教育水平任务，更少用于个人用例。例如，使用 Claude 6 个月或更久的人，个人对话减少 10%，其输入反映的教育水平提高 6%。最引人注目的是，这一较高使用年限群体在对话中的成功率高出 10%，这种关联无法用他们的任务选择、来源国或其他因素解释。虽然这可能反映早期采用者的成熟度，但也可能是"干中学"（learning-by-doing）的证据——人们通过经验变得更善于使用 Claude。

## 自上次报告以来的变化
### Claude.ai 用例的多样化
我们首先看 Claude 被要求执行的任务类型。我们使用[隐私保护系统](<https://arxiv.org/abs/2412.13678>)，它使我们能够在聚合层面描述行为，而不泄露单个转录的内容。我们从[Claude.ai](<https://cdn.sanity.io/files/4zrzovbb/website/f065d6e6f92c65df8244042c83d48872ea308c3a.pdf>)（我们的面向消费者的网页产品）和我们的第一方 API（面向开发者的、将 Claude 集成到产品和流程中的接口）各抽取 100 万次对话。2
编码仍然是我们平台上最常见的用途，与计算机和数学职业相关的任务占 Claude.ai 对话的 35%（见[附录](<https://cdn.sanity.io/files/4zrzovbb/website/a3cdcd9e67c3c4c51440429dd016cacba514b35b.pdf>)）。3 然而，在 2025 年 11 月至 2026 年 2 月期间，Claude.ai 上的用例变得更加分散：最常见的 10 个 O*NET 任务占对话的比例从 24% 降至仅 19%（图 1.1）。
这种集中度的下降部分反映了编码任务从 Claude.ai 迁移到我们的第一方 API，Claude Code 已占抽样流量的很大一部分。Claude Code 的智能体架构将编码工作拆分为更小的 API 调用，这些调用被标记为不同的任务。因此，虽然编码在 API 流量中的总体份额有所增长，但它分散在众多任务类别中，而不是集中在少数几个。结果，尽管编码活动涌入，API 中的任务集中度大致保持平稳。
![](assets/economic-index-march-2026-report/img_001.img)_**图 1.1：按平台（Claude.ai 和 1P API）划分的前 10 大任务在不同时期的使用份额。** 按平台和报告版本，分配给十个最常见 O*NET 任务的对话份额。_  

编码从 Claude.ai 迁移并不是推动集中度下降的唯一因素。部分下降源于两个时期之间用例构成的变化。课程作业从占对话的 19% 下降到 12%，而个人使用从占对话的 35% 上升到 42%。课程作业下降的一部分可以用学术日历解释——在我们抽样期间，一些国家的学生正处于寒假。4 与此同时，2 月前后注册量的增加带来了更多普通 AI 用户。
![](assets/economic-index-march-2026-report/img_002.img)_**图 1.2：2025 年 11 月和 2026 年 2 月 Claude.ai 上的工作、个人和课程作业使用。** Claude.ai 上被识别为工作、个人或课程作业相关对话的份额。_  

虽然 Claude 工作任务的范围变得更加多样化，但几乎所有这些任务之前都曾出现在我们的数据中。在上一份报告中，我们指出 49% 的职业中至少有四分之一的职业任务是通过 Claude 完成的。在这次数据抽取中，这一累计估计几乎没有变化（[附录](<https://cdn.sanity.io/files/4zrzovbb/website/a3cdcd9e67c3c4c51440429dd016cacba514b35b.pdf>)图 A.2）。本报告的数据显示，新颖的 O*NET 任务比上一份报告少得多。
自第一份报告以来，我们将对话分为五种交互类型之一——指令式（directive）、反馈循环（feedback loop）、任务迭代（task iteration）、验证（validation）和学习（learning）——并将它们归为两个更广泛的类别：自动化（automation）和增强（augmentation）。5 图 1.3 显示 Claude.ai 中的增强略有增加。这由验证和学习模式的小幅上升推动。在[附录](<https://cdn.sanity.io/files/4zrzovbb/website/a3cdcd9e67c3c4c51440429dd016cacba514b35b.pdf>)图 A.3 中，我们显示 1P API 数据中的自动化急剧下降。
![](assets/economic-index-march-2026-report/img_003.img)_**图 1.3：协作模式份额，Claude.ai。** Claude.ai 中各 Anthropic 经济指数报告的协作模式频率。_  

我们的 API 平台继续获得相对更高的计算机和数学任务份额（按职业类别划分的使用份额见[附录](<https://cdn.sanity.io/files/4zrzovbb/website/a3cdcd9e67c3c4c51440429dd016cacba514b35b.pdf>)）。自 2025 年 8 月以来，该类任务在 API 中的份额增加了 14%，在 Claude.ai 中下降了 18%。正如我们在[劳动力市场影响](<https://www.anthropic.com/research/labor-market-impacts>)报告中指出的，我们预计这种从 Claude.ai 向 API 的迁移可能预示着相关职业的工作将更迫近地发生转变。Claude.ai 中与管理工作相关的任务增加——从占流量的 3% 上升到 5%——来自分析类任务（如准备投资备忘录）和回答客户问题的混合。
衡量 Claude 上任务组合变化的另一种方式是看任务平均价值的变化，我们将其定义为执行该任务的美国工人的平均小时工资（图 1.4）。6 Claude.ai 中任务价值的这一估计从 49.3 美元略微下降到 47.9 美元，主要是因为简单事实性问题（如体育赛果、天气）的增加，以及编码向 API 迁移导致的减少。正如我们在[上一份报告](<https://www.anthropic.com/research/anthropic-economic-index-january-2026-report>)中提到的，我们在 Claude 上看到的任务往往需要更高的教育水平。该图显示这些任务往往也比美国全国平均工资赚得更多。
![](assets/economic-index-march-2026-report/img_004.img)_**图 1.4：不同版本和平台间平均任务价值的变化。** 此图使用 O*NET 框架估计在 Claude.ai 和 1P API 上执行任务的价值。任务价值估计为执行该任务的工人所得的平均小时工资。_
虽然幅度不大，但上一份报告与本报告之间几个原语的变化捕捉到了 Claude.ai 上任务复杂度的类似下降。人类输入所需的平均受教育年限从 12.2 年下降到 11.9 年，用户授予 AI 的自主性增加，人类单独完成该任务所需的时间减少了约 2 分钟。有一个变化表面上方向相反：Claude 执行的任务被认为在没有 AI 的情况下人类完成的难度略增。
![](assets/economic-index-march-2026-report/img_005.img)_**表 1.1：关键原语的变化。** 此表显示 Claude.ai 中平均原语与上一份经济指数报告的比较。除"人类单独时间"（p<0.05）外，所有差异在 p<0.001 下均具有统计显著性。这些原语的定义见附录。_
### 新兴的自动化模式
随着任务迁移到 API，它们可能更容易受到自动化的影响。API 工作流更可能是指令式的，对人机协同的需求更少。在[上一份报告](<https://cdn.sanity.io/files/4zrzovbb/website/a42bc3fc08283562f08fd8bdee8f6f9a3d506e87.pdf>)中，我们强调客户服务任务——例如支付和账单问题的自动化支持——在 API 数据中很普遍。这些任务导致了客户服务代表观察到更高的暴露度——Claude 被记录到在自动化工作流中完成其任务的很高比例，因此随着 AI 扩散，这些职业可能更可能发生变化。
我们重点介绍两个与三个月前相比在 2 月出现更频繁的 API 工作流，它们在我们最新样本中的份额至少翻了一番：7
  * **商务销售与外联自动化：**销售赋能内容生成、B2B 线索资格研究、客户数据丰富、冷邮件起草。
  * **自动交易与市场运营：**监控市场或头寸、提出具体投资建议、告知交易员市场状况及相关任务。

### 重新审视地理趋同
在上一份报告中，我们指出 Anthropic AI 使用指数（AUI）——按地理区域的劳动年龄人口调整使用量——在美国各州之间迅速趋同：人均使用量初始较低的州显示出更快的采用速度。
图 1.6 的左图显示，这种趋同在我们最新数据中仍在继续，但速度较慢。从 2025 年 8 月到 2026 年 2 月，前五州的人均使用份额从 30% 下降到 24%。基尼系数自 2025 年 8 月以来有所下降，但趋同速度已经放缓。当我们更新[上一份报告](<https://www-cdn.anthropic.com/096d94c1a91c6480806d8f24b2344c7e2a4bc666.pdf>)中的估计时，我们发现按照这个速度，各州大约需要 5-9 年才能达到大致相等的人均使用量，而不是 2-5 年。8
![](assets/economic-index-march-2026-report/img_006.img) _**图 1.5：地理趋同。** 此图显示美国各州（左图）和国家（右图）的 Anthropic 使用指数洛伦兹曲线。_

## 学习使用 AI
在本章中，我们聚焦于反映人们如何部署和学习使用 AI 的两个使用特征：模型选择和老用户的使用习惯。
首先，我们通过研究人们何时选择我们性能最强的模型类别 Opus，来揭示对智能的需求。关于 AI 用户如何在模型之间做选择、如何权衡速度、性能和成本，人们知之甚少。如果用户在针对手头任务进行校准，我们应该看到 Opus 集中于更困难、更有价值的工作。
接下来，我们研究使用情况如何按使用年限（tenure）不同而变化，发现不同时期注册的用户之间存在差异。这揭示了学习曲线：经验丰富的用户会随时间变得更好吗？他们的使用有何不同？我们发现了与"干中学"一致的证据。使用年限较长的用户不仅在对话中成功率更高，而且与 Claude 协作更多，带给 Claude 更具挑战性的任务，并且更可能将 Claude 用于工作目的和更广泛的任务范围。
### 模型选择
不同的 Claude 模型类别（Haiku、Sonnet 和 Opus）在成本、速度和性能方面提供不同的取舍。Opus 类模型使用最多的令牌，擅长复杂任务，但在我们 API 上的每令牌价格也更高。如果用户意识到这一点并关注成本和用量限制，他们应该把最复杂、最有价值的任务交给 Opus，而为更简单的任务选择其他模型。这大体上就是我们在数据中观察到的。
下面的图 2.1 显示，对于可以使用所有模型类别的付费 Claude.ai 账户，55% 的计算机和数学任务（如编写软件）使用 Opus，而教育类任务为 45%。技术用户可能会注意到性能提升，并主动从默认的 Sonnet 切换。或者注重效率的用户可能学会对更简单的任务使用 Sonnet，以避免触及用量限制。与此相关的是，这里的差异可能反映大多数教育任务对 Sonnet 来说已经相当容易，或者学生更可能注意用量限制。
![](assets/economic-index-march-2026-report/img_007.img)_**图 2.1：模型选择与职业领域。** 此图显示付费 Claude.ai 用户根据任务所属职业领域，对 Opus 类模型的选择高出或低于平均值的程度。在此样本中，51% 的总体使用是 Opus，55% 的计算机和数学使用（+4.4 个百分点）是 Opus。_
下面的图 2.2 以更细粒度的方式展示这一点。当用户执行与工资较高_职业_相关的任务时，他们更常使用 Opus。例如，在 Claude.ai 上，34% 的软件开发人员任务涉及 Opus，而辅导教师任务仅为 12%。总体而言，任务的每小时工资每增加 10 美元，Claude.ai 用户使用 Opus 的对话份额就增加 1.5 个百分点。1P API 流量对任务复杂度的响应要大得多。其斜率约为两倍，任务价值每增加 10 美元，Opus 份额增加 2.8 个百分点。与网页用户相比，部署程序化工作流的用户可能更有理由在模型之间切换。
![](assets/economic-index-march-2026-report/img_008.img)_**图 2.2：模型选择与职业。** 此图显示用户根据任务关联的职业选择 Opus 类模型的频率。每个点是一个职业（x 轴）及其 Opus 份额（y 轴）。左图显示 Claude.ai 用户，右图显示 1P API 用户。_  

### 学习曲线
第一个 Claude 模型于 2023 年 3 月发布。此后，Claude.ai 和 API 上的用户群迅速增长。我们最新的样本包含各种用户，有些人在第一个 Claude 版本发布时就注册了，有些人则在我们测量其使用的前一天才注册。一个人在 Claude 上的使用年限如何塑造其体验？9
表 2.1 显示低使用年限用户和高使用年限用户之间的差异，其中后一组定义为至少 6 个月前注册 Claude 的用户，低使用年限用户是其他所有人。10 高使用年限用户更可能使用 Claude 迭代他们的工作，而通过指令式使用模式委托更大责任的可能性低得多。他们使用 Claude 工作的可能性高 7 个百分点，并且使用 Claude 处理往往需要更高教育水平的任务。最后，他们的使用在特定任务上的集中度更低。前 10 大 O*NET 任务在高使用年限群体中占使用量的份额略低（20.7%，而低使用年限为 22.2%）。

在左图中，我们显示理解人类提示所需的受教育年限每增加一年 Claude 使用时间就增加近 1 年。在右图中，我们显示与此同时个人使用减少：一年前注册的人将 38% 的对话用于个人用例，而最新用户为 44%。
![](assets/economic-index-march-2026-report/img_010.img)_**图 2.3：使用年限与受教育年限和个人使用的相关性。** 此图显示两个分箱散点图。左图显示人类受教育年限与注册后天数的关系。右图显示个人使用对话的百分比与注册后天数的关系。_  

对于一种快速进步的通用的技术，其用户群中的这些模式可能由几个因素造成。高使用年限用户是自我选择的，这里的差异可能反映稳定的特征。例如，他们可能是计算机程序员，更可能是早期采用者。此外，存在固有的幸存者偏差：在我们数据抽取前一年注册的人可能正在看到他们使用的积极结果。我们观察不到一年前注册但不再使用 Claude 的人。
这些发现与我们在经济原语报告中看到的相呼应：低收入、教育程度较低的国家在某些情况下反而显示出更复杂的使用。最早的采用者往往有高价值的技术用例。在采用率低得多的较贫穷国家，这些早期采用者仍然主导着用户群。
当 AI 扩散到更广泛的人口比例时，更随意的使用才会出现。事实上，在请求聚类中，平均使用年限最高的任务包括：AI 研究、git 操作、修订手稿和初创公司融资。平均使用年限最低的任务有更简单的工作流，如写俳句、查看体育比分和为派对推荐食物。11
#### 经验效应
我们在下面的图 2.4 中更深入地探索这些关系，使用对数级数据对对话特征进行细粒度控制。在顶图中，规范（1）显示了一个简单的双变量回归，以任务成功为结果变量，以长期使用指标为预测变量。成功是 Claude 对对话是否成功的评估，[在我们的上一份报告中有所描述](<https://www-cdn.anthropic.com/096d94c1a91c6480806d8f24b2344c7e2a4bc666.pdf>)。该图显示长期使用用户拥有成功对话的可能性高出约 5 个百分点。
这可能反映使用年限较长的用户更善于提示。但如果这反映的是他们带给 Claude 不同的任务——那些更可能成功的任务呢？
在规范（2）中，我们加入了特定 O*NET 任务和请求聚类的固定效应。这相当于在同一个狭义定义的任务内比较高使用年限和低使用年限用户，而不是跨任务比较。例如，我们有一个名为"对特定公司执行公司财务分析、估值和建模"的请求聚类。固定效应在该聚类内比较高、低使用年限用户，并在每个其他聚类内同样比较。只有当平均而言，长期使用用户在这些任务内比较中更成功时，我们才会观察到正系数。这一控制使效应有所缓和，接近 3 个百分点。
![](assets/economic-index-march-2026-report/img_011.img)_**图 2.4：经验与成功之间的关联。** 此图显示将我们的二元成功度量对高使用年限指标进行回归的结果，控制条件越来越严格。系数以百分点给出，须线给出 95% 置信区间。"任务固定效应"表示 O*NET 任务和请求聚类的固定效应。完全控制增加了模型、用例和国家固定效应。_  

  
最后，我们问这种关系是否受到使用年限较长的用户选择不同模型、使用不同语言交流、有不同的用例或在不同国家注册的影响。这个回归产生的高使用年限影响略高，表明在完全控制下成功率高出 4 个百分点。
这些结果表明，高使用年限用户在 Claude 对话中更成功，而且这不是由语言或所执行任务等简单因素造成的。一个有趣的潜在解释是，这些用户更好地学会了如何从 AI 中提取他们想要的东西。对这些平台的熟练度可能是成功的关键决定因素，而且似乎随经验而增长。
## 讨论
本报告重新审视了我们用来跟踪 Claude 使用的核心指标，并首次分析了模型选择和成功率。自 2025 年 8 月以来，1P API 使用变得更加集中，前 10 大 O*NET 任务现在占流量的 33%，高于 28%。另一方面，Claude.ai 的任务自 2025 年 11 月的数据以来已经多样化。美国低使用州中更快的采用仍在继续，尽管速度比上一份报告慢。低采用国家则略进一步落后。
有了这份报告，我们可以开始追踪各种经济原语如何变化。课程作业占使用量的份额下降，而个人对话增加。我们还注意到 Claude.ai 中提示的总体复杂度略有下降，Claude.ai 中的对话表现出更不复杂的输入和更短的估计完成时间。
总体而言，Claude 被用于高价值、复杂的工作，这些工作并不能广泛代表美国经济。但随着用户群的扩大，报酬较低的任务占流量的份额略增。任务的平均价值——以与这些任务相关的职业中工人所得估计工资衡量——自第一份报告以来在 Claude.ai 上有所下降，而在 API 用户中上升。在两个平台上，用户都将最复杂的任务交给我们更强大的模型类别 Opus。这种转折在 API 客户中更明显。
更有经验的用户往往更协作地使用 Claude，更多出于工作相关原因，处理更复杂的任务，并且成功率更高。这与我们去年提出的一个假设相抵触，即自动化使用可能更有经验的、成熟的用户所特有；相反，我们发现最先进的用户更可能与 Claude 迭代。这也与"干中学"一致：一个人花在 AI 上的时间越多，就越善于驾驭它。
当然，另一种解释是这些结果由队列效应或幸存者偏差驱动。早期采用者可能更懂技术。继续使用 Claude 的人可能是那些拥有 Claude 特别擅长完成的任务的人。但经过仔细控制的回归排除了这种混杂的简单版本，比如长期使用用户带来不同类型的任务。随着时间推移，我们将能够更干净地将队列效应和幸存者偏差与"干中学"区分开来。
这些观察到的成功率差异可能加深劳动力市场的不平等。经济学家长期以来一直注意到[技能偏向型技术变革](<https://www.aeaweb.org/articles?id=10.1257/0022051026976>)的可能性：提高高技能工人工资的同时压低其他工人工资的创新。我们在这份报告中的分析识别了一个这类技能偏向型转变可能已经在发生的渠道：拥有高技能任务的早期采用者与 Claude 的交互比后来的、技术性较弱的采用者更成功。这些早期采用用户可能同时是[最暴露于](<https://www.anthropic.com/research/labor-market-impacts>)AI 驱动的颠覆的人群，也是在这些最初的、增强性的采用浪潮中最受 AI 帮助的人群。
